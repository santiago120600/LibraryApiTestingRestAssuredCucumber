# Library API Testing

Automated tests for Library API using Cucumber and RestAssured.

## How to Run

```sh
docker-compose up --build
```

## Configuration Flags

Tests are run with `mvn test` and controlled through four system properties passed as Maven flags (`-D<flag>=<value>`).

### `-Dtest` — Select the test runner

A Maven Surefire flag that picks which Cucumber runner class to execute. Each runner is bound to a Cucumber tag expression:

| Runner | Tag expression | Purpose |
| --- | --- | --- |
| `io.github.santiago120600.runners.BookTestRunner` | `@BookRegression` | Book API scenarios |
| `io.github.santiago120600.runners.AuthorTestRunner` | `@AuthorRegression` | Author API scenarios |
| `io.github.santiago120600.runners.ETETestRunner` | `@BookRegression or @AuthorRegression` | End-to-end (both suites) |

```sh
mvn test -Dtest="io.github.santiago120600.runners.BookTestRunner"
```

### `-Denv` — Select the target environment

Controls which base URL the tests hit. Read in `Hooks.setEnv()` via `System.getProperty("env", "mock")`:

| Value | Base URL key | Target |
| --- | --- | --- |
| `mock` (default) | `mock.base.url` | Mountebank stubs |
| `prod` | `prod.base.url` | Real Library API |

Any unrecognized value falls back to `mock`.

```sh
mvn test -Dtest="io.github.santiago120600.runners.BookTestRunner" -Denv="prod"
```

### `-Dconfig` — Select the properties file

Controls which properties file is loaded by `Utils.getGlobalValue()` and whether request/response logging is enabled. Read via `System.getProperty("config", "docker")`:

| Value | Properties file | Hostnames | Logging |
| --- | --- | --- | --- |
| `docker` (default) | `global.properties` | Docker service names (`mountebank:5555`, `mitmproxy:8866`) | Off |
| `local` | `global-local.properties` | `localhost` URLs (`localhost:5555`, `localhost:8866`) | On (Rest Assured request/response filters) |

```sh
mvn test -Dtest="io.github.santiago120600.runners.BookTestRunner" -Denv="mock" -Dconfig="local"
```

> **Note:** When running locally, `-Dconfig="local"` must be set. Without it the tests default to `docker` and try to reach Docker service names that aren't resolvable from the host.

### `-Dproxy` — Enable/disable the mitmproxy

Controls whether Rest Assured routes test traffic through mitmproxy. Read in `Hooks.setup()` via `System.getProperty("proxy", "true")`:

| Value | Behavior |
| --- | --- |
| `true` (default) | Traffic flows through the proxy URL from the selected properties file (`proxy.base.url`) |
| `false` | No proxy; requests go directly to the base URL |

The proxy URL is resolved from the properties file chosen by `-Dconfig`:

- `global.properties` (Docker runs): `proxy.base.url=http://mitmproxy:8866`
- `global-local.properties` (local runs): `proxy.base.url=http://localhost:8866`

```sh
mvn test -Dtest="io.github.santiago120600.runners.BookTestRunner" -Denv="mock" -Dconfig="local" -Dproxy="true"
```

See the [Proxy Configuration](#proxy-configuration) section for details on the mitmproxy container and its web UI.

### Full example

```sh
# Local run: mock environment, local config, proxy disabled
docker compose up -d --build mountebank
mvn test -Dtest="io.github.santiago120600.runners.BookTestRunner" -Denv="mock" -Dconfig="local" -Dproxy="false"

# Docker run: mock environment, docker config (defaults)
docker-compose up --build
```

## Proxy Configuration

The project uses **mitmproxy** to intercept and inspect HTTP traffic generated by Rest Assured during test runs. This is useful for debugging API requests and responses.

### How it works

The proxy is controlled at two layers:

1. **mitmproxy container (Docker)** — `docker-compose.yaml` defines a `mitmproxy` service that exposes:
   - Port `8866` — the proxy endpoint that test traffic flows through
   - Port `8081` — the web UI for inspecting captured requests

2. **Java test code (`Hooks.java`)** — the proxy toggle is the `-Dproxy` system property, which defaults to `true`:

   ```java
   String proxy = System.getProperty("proxy", "true");
   if (Boolean.parseBoolean(proxy)) {
       RestAssured.proxy(Utils.getGlobalValue("proxy.base.url"));
   }
   ```

   The proxy URL is read from the properties files depending on the environment:
   - `global.properties` (Docker runs): `proxy.base.url=http://mitmproxy:8866`
   - `global-local.properties` (local runs): `proxy.base.url=http://localhost:8866`

### Enable the proxy

**Docker run** (uses `global.properties`):

```sh
docker-compose up --build
```

The `restassured` container inherits `PROXY_FLAG` from `.env`, but the Java code reads the `-Dproxy` system property, which defaults to `true`. So the proxy is enabled by default in Docker runs.

**Local run** (uses `global-local.properties`):

Start the mitmproxy container first, then run tests with the proxy enabled:

```sh
docker compose up -d mitmproxy
mvn test -Dtest="io.github.santiago120600.runners.BookTestRunner" -Denv="mock" -Dconfig="local" -Dproxy="true"
```

### Disable the proxy

```sh
mvn test -Dproxy="false"
```

### Proxy UI

Visit `http://localhost:8081/` and enter the password defined in the `.env` file (`MITMPROXY_WEB_PASSWORD`).

### Run locally

```sh
docker compose up -d --build mountebank
mvn test -Dtest="io.github.santiago120600.runners.BookTestRunner" -Denv="mock" -Dconfig="local" -Dproxy="false"
```

### Note on PROXY_FLAG

The `PROXY_FLAG` environment variable in `.env` / `docker-compose.yaml` is passed to the `restassured` container but is not currently wired into the Java test code. The Java side reads the `-Dproxy` system property instead. To bridge this gap, the `PROXY_FLAG` env var would need to be mapped to the `-Dproxy` system property in the test runner or Dockerfile.
